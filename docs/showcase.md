# Showcase

The showcase registry holds applications that show what a self-hosted
model platform makes possible. Each runs on a single GPU workstation,
and several are built to compose into larger ones.

```sh
marigold registry add https://demos.marigold.run/
```

## Your own data

Your files stay on your machine, and the models come to them.

| Application | What it does | Models |
|---|---|---|
| `photo-memory` | search your photographs by description: "the beach, summer 2019" | image-embedding, img2txt, text-embedding, instruct |
| `notes-rag` | ask questions of your own documents, with the passages each answer came from | text-embedding, instruct |

## Agents

| Application | What it does | Models |
|---|---|---|
| `agent-feed` | a swarm of agents posting, reading and replying in a shared feed, all on one GPU | instruct |

## Building a world

Each of these is useful alone. Together they supply a game.

| Application | What it does | Models |
|---|---|---|
| `level-writer` | a level layout from a short brief: rooms, props, characters | instruct |
| `texture-forge` | tiling textures from prompts, regenerated until they pass a quality check | txt2img, image-eval |
| `sound-forge` | sound effects and ambience from prompts | txt2audio |
| `npc-voice` | a character sheet in, spoken dialogue out | instruct, tts |
| `depth-scene` | photographs turned into walkable 2.5D scenes | depth, img2mask |

## generated-world

A first-person game in the browser whose world, sounds and characters
are generated on your machine. You speak to its characters, and they
answer in their own voices.

```sh
marigold application install generated-world
marigold cache populate generated-world
marigold application start generated-world
```

`generated-world` requires `level-writer`, `texture-forge`,
`sound-forge` and `npc-voice`, and installing it installs them. `cache
populate` downloads the models of all five. It
shows:

- several applications composed through `requires`;
- models shared through one cache;
- real-time dialogue: speech in, text, speech out, under a second.

## For Marigold

Existing open-source applications, ported to run on the platform and
published by their own projects. A port keeps the application's
interface and data, and hands its models to the platform, so it shares
one cache and one queue with everything else on the host.

This list is open: if you maintain an AI application, a port is a
`marigold.toml`, a `models.yaml` and a change of base URL. See
[Porting](porting.md).

## Contributing

A showcase application is an ordinary Marigold application. Build it as
described in [Building](building.md), or port an existing one as
described in [Porting](porting.md), publish it in your own registry,
and open an issue on the
[marigold repository](https://github.com/bayinfosys/marigold) to have it
listed here.
